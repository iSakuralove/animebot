# PRD：动漫频道检索 bot

## 一句话

在自己频道已发布的 1639 个动漫帖子上做检索：输入名字，判断发过没有，发过就给原帖链接。

## 为什么需要

频道从 2022-04 到现在发了 2905 条消息、1639 个番剧帖。人要找一部番，只能靠
Telegram 客户端搜索或者翻那份 Google 表格。两个都不好用：客户端搜索不认标签、
不容错别字；表格要另开浏览器，而且是全频道公用的一份，没法按标签筛。

## 硬约束（决定了整个架构）

**Bot API 读不到频道历史消息。** 没有 `getChatHistory`，没有 `searchMessages`
—— 那些是 MTProto（用户账号）的能力。Bot 只能收到它加入频道之后的新
`channel_post`。1639 个历史帖对 bot 来说等于不存在。

所以数据来源必须是两条腿：

- **全量回填**：Telegram Desktop 导出 JSON，手动一次
- **增量维护**：`channel_post` + `edited_channel_post`

**帖子会被反复编辑。** 真实数据里 2847/2849 条消息有 `edited` 字段。补链接、
改评分、换网盘都是编辑而不是重发。所以增量同步必须处理编辑事件，写入必须幂等。

**格式跨四年半漂移过。** 评分前缀有 `☺️`(1266) / `⭐️`(190) / 无(21) / `个人`(6)
四种；百度网盘有 7 种 emoji 变体；`引索` 出现 1496 次而 `索引` 0 次（笔误已成事实标准）。
解析器要适应已发布的数据，不能要求回头改 3000 个帖子。

**1500+ 个帖子的下载链接藏在 entity 里。** 可见文字只有「点击下载」「打开」，
甚至有锚文本是单个 `\n` 的隐藏链接。链接必须靠 entity 偏移按行归属。

## 范围

### 已交付

| 功能 | 说明 |
|---|---|
| 全量回填 | 从导出 JSON 灌库，幂等，带频道 id 校验 |
| `/search` | 多词、错别字容错、`#标签` 筛选 |
| `/check` | 只回答发过 / 没发过 |
| `/tags` | 标签列表 + 拼音首字母索引 |
| `/help` | 从注册表自动生成，加指令不用手写帮助 |
| `/ping` `/trace` | 测活、看本次请求的追踪信息 |
| `/health` `/metrics` | 管理员专用 |
| CLI | `ingest` / `stats` / `search` / `commands` / `run` |
| 模块化框架 | 加模块 = 建一个包 + 加一个名字，不改已有文件 |
| 可观测性 | trace_id 全链路、结构化日志、进程内埋点 |

### 路线图

按依赖顺序，不是愿望清单：

1. **增量同步** —— 当前唯一有时效性的缺口。数据是 2026-09-05 快照，之后发的帖子不进库。
   设计见 [design/incremental-sync.md](design/incremental-sync.md)。
2. **搜索分页** —— `#漫改` 有 572 个帖子，现在只返回 8 条。
3. **`/bgm`** —— 查 Bangumi。第一个真外部 API 模块，验证 `HttpClient` 够不够用。
4. **`/agent`** —— LLM 问答。范围待定（只答频道里有的 / 通用动漫知识），
   这个决定会导致完全不同的架构。
5. **监控与部署** —— 单实例锁、health 聚合、心跳推送。见 [operations.md](operations.md)。

### 明确不做

| 不做 | 理由 |
|---|---|
| 导出图片 | 导出格式里没有 `file_id`；`file_id` 是 per-bot 凭证，别人的用不了。搜索结果走原帖深链，图片由 Telegram 渲染。 |
| MTProto 用户账号爬频道 | 要手机号登录，有风控风险。导出 JSON 已经够，不需要第二条历史来源。 |
| FTS5 全文索引 | 实测 trigram 对中文 2 字查询全部未命中，而 LIKE 全表扫 0.5~3ms。见 [ADR-0003](ADR/0003-no-fts5.md)。 |
| 在 bot 里重新渲染帖子 | 原帖有图、有按钮、有格式，重渲必然不一致。深链一行顶掉整套渲染管线。 |
| Redis / 外部消息队列 | 单实例部署，进程内存够用。限流和缓存的接口留了，换实现不改调用方。 |
| Web 管理后台 | `/health`、`/metrics`、CLI 已经覆盖调试需求。 |
| Prometheus exporter | 埋点数据结构留了 `snapshot()`，真需要时导出即可。现在架一套基础设施不值得。 |
| 端到端金丝雀探测 | 需要真人测试账号（bot 不能给 bot 发消息），风控风险 > 收益。 |

## 验收标准

### 数据质量（有回归测试守着）

基线是 2026-09-05 从 1639 个真实帖子实测的，[test_parser_golden.py](../tests/test_parser_golden.py)
把这些数字写成了下限：

```
消息 2905  ok 1504  partial 135  failed 0  skipped 1266  帖子 1639
```

- `failed` 必须**永远**是 0。有标题却认不出来 = 解析器漏了写法。
- 每个字段的填充数不许下降。加别名可以让它涨，不能让它跌。
- 出现 ≥5 次的未知字段名会让测试红 —— 说明别名表漏了写法。

| 字段 | 覆盖率 | 字段 | 覆盖率 |
|---|---|---|---|
| title_cn | 100.0% | links | 98.4% |
| passwords | 98.2% | tags | 97.4% |
| summary | 96.6% | index_tags | 91.3% |
| staff | 90.4% | episodes | 90.3% |
| score | 89.7% | air_date | 83.5% |

### 检索质量（有测试守着）

| 输入 | 期望 |
|---|---|
| `无职英雄` | 精确命中 |
| `无职英雄 技能` | 命中 2 词的排第一 |
| `咒术回站` | 纠错到「咒术回战」 |
| `白色相薄2` | 排第一的是「白色相簿2」，不是「白色相簿」 |
| `#奇幻 #异世界` | 标签交集 |
| `#校园 英雄` | 标签过滤 + 关键词 |

### 工程质量

- `uv run pytest` 全绿
- `uv run ruff check src tests` 无告警
- 加一个新指令模块不需要改 `app.py` / `cli.py` / 任何已有文件
- 用户看到的错误：`UserError` 给原文，真 bug 给 8 位 trace_id，永不喷栈追踪

## 用户与权限

只有两种角色，不做更细的：

- **普通用户** —— `/search` `/check` `/tags` `/help` `/ping`
- **管理员**（`ANIMEBOT_ADMIN_IDS`）—— 额外有 `/health` `/metrics`

## 非功能要求

| 项 | 目标 | 现状 |
|---|---|---|
| 搜索延迟 | < 100ms | 实测 LIKE 0.5~3ms + rapidfuzz 10ms |
| 数据规模 | 万级帖子内不换架构 | 当前 1639，SQLite 单表 |
| 部署形态 | 单进程、单文件数据库 | SQLite WAL |
| 启动失败 | 配置/依赖错误必须启动期就炸 | `Container.require()` + `ConfigError` |
| 崩溃隔离 | 一个指令崩了不能拖垮 polling | `ErrorBoundary` 中间件，有测试 |
