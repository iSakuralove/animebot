# Post 字段字典

字段来源、真实覆盖率、别名写法。数字是 2026-09-05 从 1639 个真实帖子实测的。

模型定义在 [domain/post.py](../src/animebot/domain/post.py)，
别名表在 [domain/fields.py](../src/animebot/domain/fields.py)（每条写法后面标了出现次数）。

## 主键与身份

| 字段 | 类型 | 说明 |
|---|---|---|
| `channel_id` | int | 导出 JSON 里的形式，**不带 `-100` 前缀**。Bot API 调用要前缀时用 `Settings.bot_api_chat_id` |
| `message_id` | int | 频道内消息 id |
| `posted_at` | datetime | 发布时间 |
| `edited_at` | datetime? | 编辑时间。真实数据里 **2847/2849** 条有这个字段 |

主键是 `(channel_id, message_id)` —— Telegram 自己的天然主键，不另造 id。
这让 upsert 天然幂等，回填和增量同步可以随便重跑。

| `title_en` | 6.9% (113) | `英文名`(114) |
| `aliases` | 极少 | `别名`(5)。按 `、,，/` 拆分 |
| `episodes` | 90.3% (1480) | `话数`(1481) |
| `air_date` | 83.5% (1368) | `放送开始`(1361)、`上映年度`(14)、`上映` |
| `air_weekday` | 73.5% (1204) | `放送星期`(1214) |
| `duration` | 极少 | `片长`(6) |
| `score` | 89.7% (1471) | `评分`(1483)、`个人评分`(6)、`豆瓣评分`、`黑猫简评` |
| `score_text` | 89.0% (1459) | 同上，取数字后面那段 |

`title_cn` 100% 不是巧合 —— 没有标题的消息会被判为 `SKIPPED`（公告、闲聊），
不进帖子集合。

`score` 的解析：`4.9 不过不失` → `score=4.9`, `score_text="不过不失"`。
拆两个字段是因为数字要能排序，而文字部分是频道自己的评价体系
（`力荐` / `推荐` / `还行` / `不过不失` / `较差`）。

## 标签

| 字段 | 覆盖率 | 来源 |
|---|---|---|
| `tags` | 97.4% (1596) | `标签：#轻改 #奇幻 #异世界` |
| `index_tags` | 91.3% (1496) | `引索：#W #WZ`（拼音首字母索引） |

`引索` 出现 **1496** 次，`索引` **0** 次。这个笔误已经是事实标准，
别名表按 `引索` 来（同时也收 `索引` 以防未来改）。

热门标签（前 15）：

```
#漫改(572) #奇幻(403) #原创(364) #搞笑(342) #轻改(278) #百合(267)
#恋爱(243) #校园(243) #后宫(229) #科幻(219) #战斗(180) #日常(171)
#治愈(169) #游戏改(129) #热血(123)
```

引索是番名拼音首字母，用于按字母浏览：`#S(150) #J(128) #Y(123) #M(113) ...`

两者存在 `post_tags` 关联表（带 `kind` 区分），因为它们是**查询维度**
—— 要支持标签交集筛选和标签云。其它 list/dict 字段是**载荷**，存 JSON 列。

### 链接的两个来源

**正文 entity（1500+ 帖子）** —— 这是主要来源，而且是个坑：可见文字只有
「点击下载」「打开」「打开表格」，有的锚文本是单个 `\n`（完全隐藏的链接）。
URL 只存在于 entity 的 `href` 里。所以必须记录 entity 在拍平文本中的偏移，
再按行号归属到对应的字段名 —— 靠正则从可见文本里猜是猜不出来的。

**inline 按钮（129 帖子，8.7%）** —— 只有 2026 年前后的新格式帖子有。
按钮文字比正文 key 干净（`百度链接`、`谷歌表格`、`OD节点`），作为补充来源。
按钮形状 143 个是 1 行 3 键，1 个是 1 行 2 键。

### `sheet` 为什么只有 45

「往期番剧汇总表格」在正文里出现 1188 次，但全频道只有 **2 个**不同的表格：

| Google Sheets id | 出现次数 |
|---|---|
| `1q2JyP3A4lok0jhkN-Tl3N3D5uo8uDJFX` | 1964 |
| `1dkruirMvu78hvf6JA9sL2ADvdQe7dnjT0xwOsIFhp44` | 90 |

这是**频道级常量**，不是每帖独有资源。所以它们进了
`fields.py` 的 `SHARED_SHEET_IDS`，解析时直接剔除，只在
`Settings.summary_sheet_url` 里出现一次。剩下的 45 个是真正帖子专属的表格。

这消除了一个字段：1639 个帖子不需要各存一份同样的 URL。

## 原始数据与诊断

| 字段 | 说明 |
|---|---|
| `raw_text` | 拍平后的完整正文。**永久保留** |
| `extra` | 认不出的 `key: value`，永不丢弃 |
| `parse_status` | `ok` / `partial` / `failed` / `skipped` |
| `parse_notes` | 解析时的特殊处理标记，如 `title_from_first_line` |
| `has_photo` | 99.2%（1626）有封面图 |

`raw_text` 和 `parse_status` 是**强制字段**，不是可选的诊断信息。理由见
[ADR-0004](ADR/0004-parse-by-alias-table.md)：格式跨四年半漂移，解析器要能整库重跑
而不必重新导出。原文在，就永远有第二次机会。

### parse_status 的判定

```
没有 title_cn 且没有任何强信号  → SKIPPED   （公告、闲聊，不是帖子）
没有 title_cn 但有强信号        → FAILED    （必须永远是 0）
有 title_cn 且强信号 ≥ 2        → OK        （1504）
有 title_cn 且有 1 个强信号或简介 → PARTIAL  （135）
```

强信号 = `title_cn` / `episodes` / `index` / `tags` / `air_date` 中命中的字段。

`FAILED` 意味着「有标题特征却认不出标题」= 解析器漏了写法，
所以回归测试断言它必须是 0。

### 派生字段

| 属性 | 说明 |
|---|---|
| `key` | `(channel_id, message_id)` 元组 |
| `search_title` | 中文名 + 英文名 + 别名拼一起，存库时转小写为 `search_blob`，LIKE 预筛用 |

## 数据库表

DDL 在 [storage/schema.sql](../src/animebot/storage/schema.sql)。三张表：

| 表 | 用途 |
|---|---|
| `posts` | 主表。list/dict 字段存 JSON 列 |
| `post_tags` | `(channel_id, message_id, kind, tag)`，`kind` 是 `tag` 或 `index` |
| `ingest_runs` | 每次回填/同步的审计记录，用来发现解析成功率的回退 |

为什么标签单独建表而别的 list 存 JSON：标签是**查询维度**（要支持交集筛选、
标签云、按标签统计），JSON 列做不到用索引。其它 list（aliases、passwords）
只在展示时整体读出，没有按元素查询的需求。
